# OpenDispatch — build spec

Single-user RSS/YouTube/podcast reader, native for macOS 15+ and iOS/iPadOS 26+. One SwiftUI multiplatform app target (`App/`, generated by XcodeGen from `App/project.yml`, bundle id `com.gauthamv.openfeed`) on a local Swift package `OpenfeedCore` (`Core/`) that holds all logic. Everything is local: SQLite on the device, no server, no accounts, no sync. Started as a Next.js PWA; this spec now describes the native app. `PORT.md` has the module-level contract.

## Architecture

- **Core (`Core/Sources/OpenfeedCore`)**, Swift 6 toolchain in Swift 5 language mode with strict concurrency. Dependencies: GRDB.swift (SQLite), SwiftSoup (HTML parsing/sanitizing); feeds are parsed with Foundation's `XMLParser`. WebKit runs the bundled Readability.js.
  - `Models/`, `Database/` (schema migrations, queries, seed + default folders, `meta`), `Support/` (HTTP with the `Openfeed/0.1` UA, time/text/URL helpers).
  - Services behind protocols, wired once in `OpenfeedServices.live(database:)`: `FeedParser` (RSS/Atom/RDF, YouTube, HN, podcasts), `FeedDetector` + `OPMLCoding`, `PageScraper` (feedless listing pages), `ContentExtractor` (article text), `RefreshService` (refresh pipeline), `IntegrationService` (Readwise/webhook), `ContentService` (cached reader content).
- **App (`App/Openfeed`)**: `AppModel` (`@MainActor @Observable`, the single source of UI state, calls the services with `await`), `AppSettings` (UserDefaults JSON), design tokens in `Design/`, views in `Views/` (Sidebar, Feed, Reader, Sources, Settings, Shared).
- Concurrency: services are `Sendable`; network and parsing work runs off the main actor; WebKit work runs on the main actor.

## Data model (SQLite via GRDB; originally Drizzle/Postgres)

```
sources: id serial pk, title text, url text (site/channel url), feed_url text unique, kind enum('rss','youtube','page'), group text ('labs'|'blogs'|'news'|'aggregator'|'youtube'), icon_url text null, last_fetched_at timestamptz null, last_error text null, seen_urls text[] null (page sources: article URLs already handled), created_at
items: id serial pk, source_id fk, guid text, url text, title text, summary text null, content_html text null (extracted full text, cached), author text null, published_at timestamptz, thumbnail_url text null, video_id text null, duration_sec int null, hn_points int null, hn_comments int null, hn_comments_url text null, is_saved bool default false, created_at; unique(source_id, guid); index(published_at desc)
meta: key text pk, value text  — stores 'last_refresh_at'
```

In the app the same tables and snake_case columns are SQLite (`Core/Sources/OpenfeedCore/Database/AppDatabase.swift`), plus: `folders` (id, title, position, created_at) with `sources.folder_id`/`position`, `kind` also allows `podcast`, and items gain `content_rendered`, `thumbnail_checked` and `audio_url`. Dates are UTC text, `seen_urls` is a JSON array, booleans are integers. Search is `LIKE` over title/summary/author/content.

## Fetching

- `DefaultRefreshService.refreshAll(force:)` (`Core/.../Fetching/`): fetches sources concurrently (12 at a time, 15 s per feed, User-Agent "Openfeed/0.1"), parses with `DefaultFeedParser`, filters to the 14-day retention window, keeps at most 100 items per fetch, dedupes (link-only for HN/aggregators), upserts by (source_id, guid), records `last_fetched_at`/`last_error`, backfills missing thumbnails from page og:images, then prunes unsaved items older than 14 days. Page sources go through `DefaultPageScraper` with `seen_urls`. YouTube: thumbnail `https://i.ytimg.com/vi/<id>/hqdefault.jpg`, summary from `media:description`.
- Stale rule: a refresh runs only if `meta.last_refresh_at` is older than 15 min (claimed in one transaction), unless forced. Triggered on launch and when the scene becomes active, by a timer while open (Settings → Data, default 15 min), by the refresh button / ⌘R / pull to refresh (forced), and on iOS by a `BGAppRefreshTask` (`com.gauthamv.openfeed.refresh`).
- Full text: `ContentService.content(forItem:refresh:)` returns cached `items.content_html` or calls `DefaultContentExtractor`: fetch the page (403 retried once with browser headers), run Readability.js in a hidden non-persistent `WKWebView` (page JavaScript off), apply the cleanup passes, sanitize with SwiftSoup (img, picture/source, pre, code, a, headings, lists, blockquote, figure, figcaption, video, shape-only inline SVG, iframes from youtube-nocookie/Vimeo), and cache it. Fallbacks: the feed's own content:encoded, then a Jina Reader render. Skipped for YouTube; podcasts use show notes from the feed.

## App behavior (replaces the HTTP API)

- Items: `AppModel` pages through `Queries.items` (views all/saved/articles/posts/video/podcasts, source or folder, search, keyset cursor on published_at desc, 50 per page).
- Sources: add (`OpenfeedServices.addSource` → `DefaultFeedDetector`: YouTube handles/channels, Apple Podcasts, alternate links, www retry, scraped-page fallback), rename, move, reorder, delete; folders likewise. OPML import/export via the file importer/exporter.
- Save/unsave is optimistic. Send to Readwise Reader (token in the Keychain) or a webhook (URL in `meta`).
- Deep link: `opendispatch://add?url=<url>` opens Add source prefilled.

## Platform

- macOS: three-pane `NavigationSplitView`, menu commands (Add Source ⌘N, Refresh ⌘R, Search ⌘F, Sidebar ⌘\, Full-screen reader ⇧⌘F, Shortcuts ⌘/, Settings ⌘,), Settings window, single-key shortcuts in the main window. Sandboxed with outgoing network and user-selected file access.
- iPhone (iOS 26): system TabView and navigation bars with Liquid Glass, no title text; the reader's Save / Open original / Share / Send to sit in the system bar; navigation stacks, pull to refresh. iPad: the three-pane layout with hardware-keyboard shortcuts.
- App icon in `App/Openfeed/Resources/Assets.xcassets` (rounded teal square with the white feed-arc glyph). ATS allows plain-http feeds, images and audio; background modes: fetch, audio (podcasts).
- Offline: the local database is the cache; the last-loaded items and cached articles open without a network.

## Non-goals

No accounts or auth, no server, no sync between devices, no multi-user. (The web app's `APP_PASSWORD`, `CRON_SECRET`, Vercel cron, PWA manifest and service worker are gone.)
