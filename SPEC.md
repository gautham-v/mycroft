# OpenDispatch — build spec

Single-user RSS/YouTube/podcast reader, native for macOS 15+ and iOS/iPadOS 26+. One SwiftUI multiplatform app target (`App/`, generated by XcodeGen from `App/project.yml`, bundle id `com.gauthamv.openfeed`) on a local Swift package `OpenDispatchCore` (`Core/`) that holds all logic. Everything is local: SQLite on the device, no server, no accounts. iCloud sync (CloudKit private database, the device's own Apple ID) mirrors the library between devices. Started as a Next.js PWA; this spec now describes the native app. `PORT.md` has the module-level contract.

## Architecture

- **Core (`Core/Sources/OpenDispatchCore`)**, Swift 6 toolchain in Swift 5 language mode with strict concurrency. Dependencies: GRDB.swift (SQLite), SwiftSoup (HTML parsing/sanitizing); feeds are parsed with Foundation's `XMLParser`. WebKit runs the bundled Readability.js.
  - `Models/`, `Database/` (schema migrations, queries, seed + default folders, `meta`), `Support/` (HTTP with the `OpenDispatch/1.0` UA, time/text/URL helpers).
  - Services behind protocols, wired once in `OpenDispatchServices.live(database:)`: `FeedParser` (RSS/Atom/RDF, YouTube, HN, podcasts), `FeedDetector` + `OPMLCoding`, `PageScraper` (feedless listing pages), `ContentExtractor` (article text), `RefreshService` (refresh pipeline), `IntegrationService` (Readwise/webhook), `ContentService` (cached reader content).
- **App (`App/OpenDispatch`)**: `AppModel` (`@MainActor @Observable`, the single source of UI state, calls the services with `await`), `AppSettings` (UserDefaults JSON), design tokens in `Design/`, views in `Views/` (Sidebar, Feed, Reader, Sources, Settings, Shared).
- Topics: a followed keyword search is a source of kind `topic` (`feed_url` `opendispatch:topic:<uuid>`, options in `topic_options`) whose refresh searches news (Bing News RSS), Hacker News, Reddit, YouTube and the iTunes episode search, with no keys, and stores the matches as items. See `PORT.md` (Topics).
- Discussions: Explore's posts and the reader's comments (`DiscussionLoading`, `DefaultDiscussions` in `Core/.../Discussions/`). Reddit refuses anything but a browser, so a hidden WKWebView on reddit.com passes its challenge and fetches its pages from inside (`DiscussionWeb`); X is read the same way, but only once the user has signed in to X in the app (the sign-in sheet's web view shares the default data store with the hidden views; the app can't see a browser's sign-ins). Bluesky, Hacker News (Algolia) and YouTube comments (innertube `next`) are open APIs. Settings → Reader → Show comments (`AppSettings.showComments`, on by default) turns the reader's comments off for every source: the comments section, the Discussion link and the on-demand Hacker News discussion are not built, so nothing is fetched for them, and turning it back on shows them without a relaunch. Explore's posts and the comment counts on rows are unaffected. See `PORT.md` (Discussions).
- Concurrency: services are `Sendable`; network and parsing work runs off the main actor; WebKit work runs on the main actor.

- Themes (`Design/Themes.swift`, Settings → Themes): one theme for light mode and one for dark (`AppSettings.lightTheme` / `darkTheme`, by id), each Default (the shipped tokens, exactly, per platform), a built-in (light: Newsprint, Sepia, Glacier, Sage; dark: Ink, Midnight, Espresso, Forest) or the user's own (`customLightTheme` / `customDarkTheme`, made from a copy of the theme in use and changed with color wells; Delete Theme goes back to Default). Settings → Appearance → Accent color (`AppSettings.accent`: the theme's, or blue, purple, pink, red, orange, yellow, green, graphite) replaces the theme's accent everywhere. The reader page gets the same palette as CSS variables after reader.css (`AppSettings.readerThemeCSS`, nil on Default with the theme's accent on the Mac, so the page keeps its own values; on iOS always set, since the Default surface there is off-white and the page's white would show as a band behind the article). Themes sync with the other settings.

The pane's title sits in the band with the close button; sections are a 13pt semibold title over a bordered rounded card (`SettingsPanelCard`) with hairlines between its rows. The macOS panel is at most 860×640. iPhone's root uses the same symbols and groups, in its usual inset squares (`GroupedIcon`).
- Light neutral: ground `#FAFAF8`, surface `#FFFFFF`, ink `#1A1A1A`, body text `#2A2A2A`, muted `#6B6B6B`, faint `#9A9A9A`, border `#E2E1DC`, hairline `#ECEBE6`, code bg `#F3F2EE`. One accent `#0F6E6E` (selected item left bar, active source name).
- Fonts: system sans (SF) for all UI and metadata (source, time, points, comments, section labels, "updated X ago", durations, counts), usually in the secondary color at the same sizes; article text in system sans by default, or serif (New York: `.design(.serif)` in SwiftUI, `ui-serif` / `-apple-system-ui-serif` in reader.css) when chosen in Settings → Reader. No monospace anywhere outside `<pre>`/`<code>` in articles. No bundled font files.
- iPhone (iOS 26, Liquid Glass): system navigation bar with no title text on any tab (no "updated X ago", no refresh button, no chips). Feed toolbar: a filter button (`line.3.horizontal.decrease.circle`, filled while a non-default choice is active) opening a menu with content type (All, Articles, Posts, Video, Podcasts) and filters (HN ≥ 100, Labs, Blogs), both single selection, plus the system search item (`.searchable`, minimized to a toolbar button). Pull to refresh. Saved and Sources use the same bare bar. The list scrolls under the glass bars; system tab bar Feed / Sources / Saved / Settings.
- Desktop (≥1024px): three panes. Sidebar 240px (app name, views All/Saved/Video with counts, Sources group, YouTube group, Filters, "+ Add source"); item list 420px; reading pane fills the rest. A source, topic or folder title runs to the row's edge and, when it doesn't fit, fades out there with no "…" (`SidebarTitleFade`). The hover "…" button sits on top of the title's end, nothing moves, and a title that reaches the button fades out just before it.
- Item row: 16pt source badge (favicon from `https://www.google.com/s2/favicons?domain=<host>&sz=64`, fallback colored monogram) · sans meta line (source · relative time; on iPhone also HN points · comments) · title (14.5/500) · optional 64×42 thumbnail on the right (play glyph for videos, duration badge for videos and podcasts). Headline only on iPhone: no snippet. - Reading pane: source badge + sans meta in the secondary color (host · date · read time); action buttons Save / Open original / Share (36px, bordered); title by the text size, on any window width (20 to 30px, 24px by default; `OFFont.headlineSize`); 640px max-width body at 17px/1.6; hero image; article HTML (sanitized); for YouTube items a 16:9 `<iframe src="https://www.youtube-nocookie.com/embed/<videoId>">` instead of body.
- No emoji; inline stroke SVG icons only. No gradients.

## Data model (SQLite via GRDB; originally Drizzle/Postgres)

```
sources: id serial pk, title text, url text (site/channel url), feed_url text unique, kind enum('rss','youtube','page'), group text ('labs'|'blogs'|'news'|'aggregator'|'youtube'), icon_url text null, last_fetched_at timestamptz null, last_error text null, seen_urls text[] null (page sources: article URLs already handled), created_at
items: id serial pk, source_id fk, guid text, url text, title text, summary text null, content_html text null (extracted full text, cached), author text null, published_at timestamptz, thumbnail_url text null, video_id text null, duration_sec int null, hn_points int null, hn_comments int null, hn_comments_url text null, is_saved bool default false, created_at; unique(source_id, guid); index(published_at desc)
meta: key text pk, value text  — stores 'last_refresh_at'
```

In the app the same tables and snake_case columns are SQLite (`Core/Sources/OpenDispatchCore/Database/AppDatabase.swift`), plus: `folders` (id, title, position, created_at) with `sources.folder_id`/`position`, `kind` also allows `podcast`, and items gain `content_rendered`, `thumbnail_checked` and `audio_url`. Dates are UTC text, `seen_urls` is a JSON array, booleans are integers. Search is `LIKE` over title/summary/author/content. `sources.notify_since` (when Notify on New Posts was turned on, null = off) is per device and not synced; `meta` `notify.through_item_id` is the highest item id already checked for notifications. `sync_records` (record_name pk, record_type, hash, system_fields) and `sync_meta` (key, value) belong to iCloud sync.

`highlights` (id uuid text pk, source_feed_url, item_guid, item_url, item_title, source_title, item_author, item_published_at, text, prefix, suffix, note, color `yellow|green|blue|pink|purple|underline`, created_at, updated_at, readwise_id, readwise_pending; index on (source_feed_url, item_guid)) holds highlights with the article's identity (not a foreign key), so they outlive item pruning (`pruneOldItems` keeps items that have highlights) and a deleted source, and a device that never had the item can list them. `text` is the quote as the reader renders it (whitespace collapsed) and `prefix`/`suffix` are about 32 characters around it. `readwise_id` is Readwise's id for the highlight once sent; `readwise_pending` and the `readwise_deletes` table queue what this device still has to send there and are local.

`history` (pk (source_feed_url, item_guid), item_url, item_title, source_title, source_kind, item_author, item_published_at, thumbnail_url, video_id, audio_url, opened_at, read_at, position_sec, duration_sec; index on opened_at) holds read state and History, keyed and snapshotted like highlights so an entry outlives the item. `opened_at` is the last time the reader showed it (NULL: marked read from a list without opening, which History leaves out, and which `pruneOldItems` drops once the item is gone); `read_at` set means read; `position_sec` / `duration_sec` are how far a video or episode got. Clearing History deletes rows, so those items are unread again.

## Fetching

- `DefaultRefreshService.refreshAll(force:)` (`Core/.../Fetching/`): fetches sources concurrently (12 at a time, 15 s per feed, User-Agent "OpenDispatch/1.0"), parses with `DefaultFeedParser`, filters to the 14-day retention window, keeps at most 100 items per fetch, dedupes (link-only for HN/aggregators), upserts by (source_id, guid), records `last_fetched_at`/`last_error`, backfills missing thumbnails from page og:images, then prunes unsaved items older than 14 days. Page sources go through `DefaultPageScraper` with `seen_urls`. YouTube: thumbnail `https://i.ytimg.com/vi/<id>/hqdefault.jpg`, summary from `media:description`.
- New-post notifications: a source's menu (Mac/iPad sidebar, iPhone drawer and Manage sources) has Notify on New Posts, which asks for notification permission the first time. Settings → Notifications lists every source with a switch for the same setting, plus Turn all off, and says whether the system allows notifications (Allow, or Open Settings when they are off). After each refresh that ran (in the app, the Mac's timer, iOS background refresh) `PostNotifications.deliver` takes `Queries.takeNewPostAlerts` (unsaved items stored since the last check, after the source's `notify_since`, published within 2 days; each handed out once) and posts local notifications: title the source, body the post title, grouped by source, at most 3 per source per refresh (more become one "N new posts, latest: …"). Nothing shows while the app is in front; tapping a notification opens the post in the reader. No push server, so they arrive as often as refreshes run, and nothing on the Mac after quitting.
- Mute (`Source.isMuted`, `Folder.isMuted`, synced): a muted source's items stay out of All, Articles, Posts, Video and Podcasts, and it stays in the sidebar; a muted folder does the same for every source filed in it, including ones added or dragged in later, and a source moved out or a deleted folder's sources are back in the feeds. The source's and folder's own lists, Saved, Highlights, History, a search, a topic's Your subscriptions and digests of a source or folder still show them; refresh and Notify on New Posts don't change. `Queries.conditions` leaves them out when the query names no source or folder and has no search, so Balanced order, the iPhone's page peeks, the new-rows pill and a view's Copy digest all follow. Mute in Feeds is in a source's menu (Mac and iPad sidebar, iPhone drawer and Manage sources), Mute Folder in Feeds in a folder's, and a feed row's menu has Mute <name> (`Source.shortTitle`); a source in a muted folder shows a disabled Muted with <Folder> there and keeps its own setting for when the folder is unmuted. A muted row is only dimmed, with no mark: the title in `ofRead` (the iPhone drawer's badge at 55%; a folder header's title, the drawer's folder icon and name too). Each change shows a toast at the bottom of the window for 6 s ("Muted Adam Schefter. Still in NFL.", `MuteToastOverlay`, above the bubbles on iPhone) with Undo. A muted source's or folder's list has a banner (`MutedListBanner`: in the header's bar on the Mac and iPad, under the title on iPhone), "Muted. Not in your feeds." with Unmute or Unmute Folder, and a folder with some muted sources says "1 of 5 sources muted. All show here."
- Remove from a row: a feed row's menu has Remove <name> under Mute <name> (not for a topic's rows or Opened links). It takes two steps, not three: the rows and the sidebar entry leave at once and a toast says "Removed <name>." with Undo (`AppModel.holdSourceRemoval`, `ItemQuery.excludedSourceIds`), and the source is deleted, closed and synced only when the toast ends or another takes its place, so quitting within the 6 s keeps it. Removing from the source's own list goes back to All and Undo returns there. A source with saved items asks first, naming how many (`SourceRemovalRequest`, held by `UndoToastOverlay` since the menu is gone by then), because saved items are deleted with their source; highlights stay. The sidebar's and Manage sources' Remove Source… keep their dialog, which now says saved items go too.
- Stale rule: a refresh runs only if `meta.last_refresh_at` is older than 15 min (claimed in one transaction), unless forced. Sources never fetched on this device (iCloud brings a source without items, perhaps while a refresh that has already read its sources is running) don't wait for that: `AppModel.refresh` ends with `refreshUnfetched`, and its list says Loading until then. Triggered on launch and when the scene becomes active, by a timer while open (Settings → Data, default 15 min), by the refresh button / ⌘R / pull to refresh (forced), and on iOS by a `BGAppRefreshTask` (`com.gauthamv.openfeed.refresh`).
- Full text: `ContentService.content(forItem:refresh:)` returns cached `items.content_html` or calls `DefaultContentExtractor`: fetch the page (403 retried once with browser headers), run Readability.js in a hidden non-persistent `WKWebView` (page JavaScript off), apply the cleanup passes, sanitize with SwiftSoup (img, picture/source, pre, code, a, headings, lists, blockquote, figure, figcaption, video, shape-only inline SVG, iframes from youtube-nocookie/Vimeo), and cache it. Fallbacks: the feed's own content:encoded, then a Jina Reader render. Skipped for YouTube; podcasts use show notes from the feed.
- Videos that won't play here (Settings → Playback; `BlockedVideoTreatment`: Show, Mark by default, Hide): some owners (the NFL's channels) keep their videos out of other apps. `items.embed_blocked` (v15: 1 won't play, 0 plays, NULL not known; per device, not in the saved item's sync record) comes from `YouTubeEmbedChecking` and from the player's errors 101 and 150, which overrule it. After the feeds, a refresh asks about each video a `youtube` source stored and up to 5 of each channel's newest not yet known, 4 at a time for at most 6 s over the whole refresh (`DefaultRefreshService.checkVideos`); no answer stays NULL and is asked again. Mark: a row says "↗ YouTube" after the source's name; a click, tap, Return or o opens YouTube and marks it read, a video included, since the app can't see it played; j/k and ⌘- or ⌥-click show the reader, whose notice appears without trying the player. Hide does the same for what still lists, and `ItemQuery.hidesBlockedVideos` leaves them out of All, Video, sources, folders and the iPhone's page peeks, with a footer counting them and Show until you leave the list; Saved, History, a search and topics keep them. Show marks nothing, and the player tries and falls back. Explore and topics aren't asked about
- Paywalls (`Core/.../Paywalls/`, `Views/Reader/ReaderPaywallBanner.swift`): an extracted article that is only the non-subscriber teaser comes back `paywalled` (`PaywallDetection`): the page has a paywall signal (JSON-LD `isAccessibleForFree: false`, `article:content_tier` locked or metered, a known paywalled site (`TopicPaywalls`), Piano or paywall markup or wording, a login wall) and the article is short (under about 300 words, or under 60% of the page's declared `wordCount`). A paywalled result is returned but not cached. The feed's own copy, Jina's copy when not walled, and X, Reddit, Hacker News and social posts are never paywalled. Any site can be signed in to: the sign-in sheet (`SignInTarget.site`) opens the article or the site's home page on the shared web data store, with Cancel and Done (Done records the sign-in); these sign-ins are per device (`SiteSignIns`, UserDefaults `openfeed.signed-in-sites`). A signed-in site's articles are read first in a hidden web view (`SignedInPages`: shared data store, JavaScript on, a 1 s settle, 15 s timeout, no images or media); a full article from it is used, anything else falls back to the normal fetch. Under a teaser the reader shows a banner: “<Site> shows the rest to subscribers.” with Sign In to <site>… (the sheet, then the article loads again with `refresh: true`) and Don’t Ask Again, and a line saying what lists do with that site's articles; once declined it is a quiet “Not signed in to <site> · Sign In…” line, and signed in but still cut short it reads “Your <site> sign-in may have expired.” with Sign In Again…. Each article opened or prefetched counts once per launch toward the synced paywall book (`AppSettings.paywalls`, a `PaywallBook`: sites that walled an article, full reads, declined); a site is paywalled when it's on the known list or has walled two articles (`Paywalls.status`), and metered when one of its articles has also read in full. Settings → Integrations → Paywalled articles (`AppSettings.paywallTreatment`, Show / Mark / Hide, default Mark) applies to paywalled sites you aren't signed in to: Mark puts a lock and “Subscribers” (metered: “May need sign-in”) in the row's meta line with a quieter title; Hide leaves walled articles out of the list (metered stay, marked; an item open in a tab stays) with a footer “N hidden from sites you don't subscribe to · Show” that reveals them until you go to another list; Saved, History, Highlights and searches never hide. A topic's story row is marked by its lead and hidden only when the lead and every outlet are walled. Below X and Reddit, “Sites with a paywall” lists every site the book knows or the app is signed in to, most walled first, with Sign In… or Sign Out, and a field adds a site by domain or address.

## App behavior (replaces the HTTP API)

- Items: `AppModel` pages through `Queries.items` (views all/saved/articles/posts/video/podcasts, source or folder, search, keyset cursor on published_at desc, 50 per page). Settings → Appearance → Feed order (`AppSettings.feedOrder`): Balanced (default) or Latest. Balanced applies to All, its Articles, Posts, Video and Podcasts views, and topics (`AppModel.listOrder`; a source, folder, Saved and a search stay newest first). Balanced ranks the first page, the newest 300 items at most and none over 48 hours older than the newest, counting each item 2 hours older for every newer item from its source, so a source that posts a lot (Hacker News, NPR) doesn't fill the top and a quiet one rises; in a topic the site stands for the source (x.com, bsky.app, youtube.com, each publisher) and story times stand for item times; below that page the list goes on newest first. Refreshing re-ranks. A refresh reloads as many rows as the list had paged in (up to 200), and rows it adds above the ones on screen don't push them down: what's on screen stays put (at the very top too) and a pill over the top of the list (`NewRowsPill`: the new rows' source icons, "4 new", an up arrow; under the header on the Mac and iPad, under the status bar on iPhone) counts the new rows still above the screen, going down as they scroll into view; clicking it scrolls to the top. SwiftUI keeps the rows in place on the Mac except at the very top, where the list puts the old first row back; iOS's List keeps its offset, so `ListAnchor` moves it to keep the top row where it was. Pull to refresh on iPhone shows the new rows at the top instead. A refresh doesn't pull the list to the default tab's item (the list's first) when that changes.
- Sources: add (`OpenDispatchServices.addSource` → `DefaultFeedDetector`: YouTube handles/channels, Apple Podcasts, alternate links, www retry, scraped-page fallback; an X profile lists only its own posts, not the ones it quotes), rename, move, reorder, delete; folders likewise. OPML import/export via the file importer/exporter.
- Add sources sheet, finding sources: a name searches X accounts, YouTube channels, Bluesky, Mastodon, Reddit communities, feeds and podcasts as you type, each landing on its own, in one list. Chips under the field (All, Posts, Video, Articles, Podcasts, each with its count) narrow it by what you'd read (`SourcePlace.readType`), so another place needs no new chip, and each row names its place; the first 8 show, then Show N More. `SourceRanking` orders them: an exact handle or name, the same name as an exact handle elsewhere, a name match, related; inside each the most followed first (Feedly readers scaled up, a community or show given a typical audience), and no place takes more than 3 of the first 8. Bots, bridges and parodies go, as does anything under 1K followers unless its handle is exact; an @ in the query keeps only that handle among accounts; a handle match under an unrelated name that nothing backs up ("fireship" on X) counts as related; related sites and shows go once anything matched; Feedly's copies of a channel and its third-party feeds of X accounts go. Sources: YouTube's search limited to channels (`ExploreSearching.channels`); `DefaultXAccounts` (one word or an @handle loads the public profile at x.com/handle, the page an X source reads, and a 404 is no account; any other name uses X's People search in the hidden web view, signed in only, with its follower count filling in the profile's, and signed out the sheet offers Sign In); `DefaultSocialAccounts` (Bluesky's public search and profiles, added as the profile's RSS by DID; mastodon.social's search, added as the profile's `.rss`; Reddit's community search in the hidden web view, added as `/r/name/.rss`, and "r/name" typed asks nothing else). The hidden-view searches wait a further 100 ms since a view can't be called off. The first three channels are asked whether their videos play in this app (`YouTubeEmbedChecking`, the embed page's `previewPlayabilityStatus` for a video from the channel's feed or, when that fails, its page, remembered while the app runs); those that don't say "Plays on YouTube only". A pasted link to an account (`SourceSearch.accountLink`: X, YouTube @handle or channel, Bluesky, a Reddit community) shows who it is and skips the feed search, and Return adds that account. Instagram, Threads, TikTok, LinkedIn, Facebook and Twitch have no public feed: a link to one says so with no add button (Instagram's profile preview also shows who it is), and the detector refuses them with the same words. A pasted Reddit community or user page adds its `.rss`, titled r/name or u/name (Reddit's page refuses the app). Results wait for every search to answer, up to 1 s after typing stops for 200 ms, faded over the last name's results (a skeleton the first time), so the list doesn't reorder as each lands; once shown, the first 8 rows stay put and anything later goes below them (`SourceRanking.keepingShown`). The sheet opens the hidden web views when it appears (`DiscussionWeb.warmForSearch`) and keeps each name's answer while it's open. Up to 16 per article, fetched in parallel with a 6 s timeout; a post that can't be read keeps its blockquote; a blockquote over 1,200 characters that only cites a post is left alone; posts themselves (X, Bluesky, Reddit…) are not expanded. The reader page sends no Referer (X's media refuse a foreign one); its iframes still send the origin, which YouTube needs.

## Platform

- macOS: three-pane `NavigationSplitView` with a hidden title bar and translucent sidebar; menu commands (Check for Updates…, Settings ⌘,, Add Source ⌘N, Refresh ⌘R, Reload Article ⇧⌘R, Listen ⇧⌘L, Search ⌘F, Filter Sources ⌘K, New Tab ⌘T, Open Link ⌘L, Close Tab ⌘W, Reopen Closed Tab ⇧⌘T, Sidebar ⌘\, Full-screen reader ⇧⌘F, Split View ⌥⌘S, next/previous tab ⇧⌘] / ⇧⌘[, Back / Forward ⌘[ / ⌘], Pin Tab, Shortcuts ⌘/); Settings is an overlay panel in the main window; reader tabs and split view (each pane's bar always shows its tabs, even one, then + for a new tab; each tab keeps what it showed before (`ReaderTab.back` / `forward`, recorded when its item or New Tab page changes, 50 deep, session only), which Back and Forward step through: ⌘[ / ⌘], the chevrons after the sidebar toggle (after the show-sidebar button when it is collapsed), a sideways two-finger swipe (`trackSwipeEvent`, when Swipe between pages is on and there is somewhere to go), a three-finger swipe, and a mouse's back and forward buttons (`ReaderNavigationGestures`); a new tab is Explore (see above): its field (focused on open and by ⌘L) searches, or opens any link, stored as an item of a built-in, unlisted source (`OpenedLinks`: one for pages, one for YouTube videos, one for podcast episodes; left out of `Queries.sources`, so never refreshed, listed, exported or synced as a source; its items list only in Saved and are pruned 14 days after opening unless saved), with no query it lists recent searches, recently read (History) and saved items, and the next item opened fills it; closing the last tab leaves a new tab, and ⌘W on that closes the window; pinned tabs (tab right-click or View › Pin Tab) sit leftmost as source badges, keep their item, so a list click or j/k on one opens a new tab after the pins, skip ⌘W and Close Other Tabs, are never repeated by the default tab (which shows the first unpinned item), and are restored on launch from UserDefaults `openfeed.pinned-tabs`, in one pane); single-key shortcuts in the main window. Updates through Sparkle from the latest GitHub release's appcast: checked about daily, downloaded in the background and installed on quit by default, and asked about first when Settings → About's switch is off (Sparkle stores the choice, and its dialog's checkbox is the same value); releases are Developer ID signed, notarized DMGs (scripts/release-mac.sh). Sandboxed with outgoing network and user-selected file access, iCloud (CloudKit, Production environment in every build) and push notifications.
- iPhone (iOS 26): a side drawer (Explore at the top, then the views, folders and sources) and Liquid Glass navigation bars with no title text; the reader's Save / Open original / Share / Send to sit in the system bar; navigation stacks, pull to refresh. iPad: the three-pane layout with hardware-keyboard shortcuts.

- Offline: the local database is the cache; the last-loaded items and cached articles open without a network.

## Non-goals

No accounts or auth of our own (iCloud sync uses the device's Apple ID), no server, no multi-user, no sync of feed items (read state and History sync, as their own records). (The web app's `APP_PASSWORD`, `CRON_SECRET`, Vercel cron, PWA manifest and service worker are gone.)
