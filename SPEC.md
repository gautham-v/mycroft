# OpenDispatch — build spec

Single-user RSS/YouTube/podcast reader, native for macOS 15+ and iOS/iPadOS 26+. One SwiftUI multiplatform app target (`App/`, generated by XcodeGen from `App/project.yml`, bundle id `com.gauthamv.openfeed`) on a local Swift package `OpenDispatchCore` (`Core/`) that holds all logic. Everything is local: SQLite on the device, no server, no accounts. iCloud sync (CloudKit private database, the device's own Apple ID) mirrors the library between devices. Started as a Next.js PWA; this spec now describes the native app. `PORT.md` has the module-level contract.

## Architecture

- **Core (`Core/Sources/OpenDispatchCore`)**, Swift 6 toolchain in Swift 5 language mode with strict concurrency. Dependencies: GRDB.swift (SQLite), SwiftSoup (HTML parsing/sanitizing); feeds are parsed with Foundation's `XMLParser`. WebKit runs the bundled Readability.js.
  - `Models/`, `Database/` (schema migrations, queries, seed + default folders, `meta`), `Support/` (HTTP with the `OpenDispatch/1.0` UA, time/text/URL helpers).
  - Services behind protocols, wired once in `OpenDispatchServices.live(database:)`: `FeedParser` (RSS/Atom/RDF, YouTube, HN, podcasts), `FeedDetector` + `OPMLCoding`, `PageScraper` (feedless listing pages), `ContentExtractor` (article text), `RefreshService` (refresh pipeline), `IntegrationService` (Readwise/webhook), `ContentService` (cached reader content).
- **App (`App/OpenDispatch`)**: `AppModel` (`@MainActor @Observable`, the single source of UI state, calls the services with `await`), `AppSettings` (UserDefaults JSON), design tokens in `Design/`, views in `Views/` (Sidebar, Feed, Reader, Sources, Settings, Shared).
- Concurrency: services are `Sendable`; network and parsing work runs off the main actor; WebKit work runs on the main actor.

## Data model (SQLite via GRDB; originally Drizzle/Postgres)

```
sources: id serial pk, title text, url text (site/channel url), feed_url text unique, kind enum('rss','youtube','page'), group text ('labs'|'blogs'|'news'|'aggregator'|'youtube'), icon_url text null, last_fetched_at timestamptz null, last_error text null, seen_urls text[] null (page sources: article URLs already handled), created_at
items: id serial pk, source_id fk, guid text, url text, title text, summary text null, content_html text null (extracted full text, cached), author text null, published_at timestamptz, thumbnail_url text null, video_id text null, duration_sec int null, hn_points int null, hn_comments int null, hn_comments_url text null, is_saved bool default false, created_at; unique(source_id, guid); index(published_at desc)
meta: key text pk, value text  — stores 'last_refresh_at'
```

In the app the same tables and snake_case columns are SQLite (`Core/Sources/OpenDispatchCore/Database/AppDatabase.swift`), plus: `folders` (id, title, position, created_at) with `sources.folder_id`/`position`, `kind` also allows `podcast`, and items gain `content_rendered`, `thumbnail_checked` and `audio_url`. Dates are UTC text, `seen_urls` is a JSON array, booleans are integers. Search is `LIKE` over title/summary/author/content. `sources.notify_since` (when Notify on New Posts was turned on, null = off) is per device and not synced; `meta` `notify.through_item_id` is the highest item id already checked for notifications. `sync_records` (record_name pk, record_type, hash, system_fields) and `sync_meta` (key, value) belong to iCloud sync.

`highlights` (id uuid text pk, source_feed_url, item_guid, item_url, item_title, source_title, item_author, item_published_at, text, prefix, suffix, note, color `yellow|green|blue|pink|purple|underline`, created_at, updated_at, readwise_id, readwise_pending; index on (source_feed_url, item_guid)) holds highlights with the article's identity (not a foreign key), so they outlive item pruning (`pruneOldItems` keeps items that have highlights) and a deleted source, and a device that never had the item can list them. `text` is the quote as the reader renders it (whitespace collapsed) and `prefix`/`suffix` are about 32 characters around it. `readwise_id` is Readwise's id for the highlight once sent; `readwise_pending` and the `readwise_deletes` table queue what this device still has to send there and are local.

`history` (pk (source_feed_url, item_guid), item_url, item_title, source_title, source_kind, item_author, item_published_at, thumbnail_url, video_id, audio_url, opened_at, read_at, position_sec, duration_sec; index on opened_at) holds read state and History, keyed and snapshotted like highlights so an entry outlives the item. `opened_at` is the last time the reader showed it (NULL: marked read from a list without opening, which History leaves out, and which `pruneOldItems` drops once the item is gone); `read_at` set means read; `position_sec` / `duration_sec` are how far a video or episode got. Clearing History deletes rows, so those items are unread again.

## Fetching

- `DefaultRefreshService.refreshAll(force:)` (`Core/.../Fetching/`): fetches sources concurrently (12 at a time, 15 s per feed, User-Agent "OpenDispatch/1.0"), parses with `DefaultFeedParser`, filters to the 14-day retention window, keeps at most 100 items per fetch, dedupes (link-only for HN/aggregators), upserts by (source_id, guid), records `last_fetched_at`/`last_error`, backfills missing thumbnails from page og:images, then prunes unsaved items older than 14 days. Page sources go through `DefaultPageScraper` with `seen_urls`. YouTube: thumbnail `https://i.ytimg.com/vi/<id>/hqdefault.jpg`, summary from `media:description`.
- New-post notifications: a source's menu (Mac/iPad sidebar, iPhone drawer and Manage sources) has Notify on New Posts, which asks for notification permission the first time. Settings → Notifications lists every source with a switch for the same setting, plus Turn all off, and says whether the system allows notifications (Allow, or Open Settings when they are off). After each refresh that ran (in the app, the Mac's timer, iOS background refresh) `PostNotifications.deliver` takes `Queries.takeNewPostAlerts` (unsaved items stored since the last check, after the source's `notify_since`, published within 2 days; each handed out once) and posts local notifications: title the source, body the post title, grouped by source, at most 3 per source per refresh (more become one "N new posts, latest: …"). Nothing shows while the app is in front; tapping a notification opens the post in the reader. No push server, so they arrive as often as refreshes run, and nothing on the Mac after quitting.
- Stale rule: a refresh runs only if `meta.last_refresh_at` is older than 15 min (claimed in one transaction), unless forced. Triggered on launch and when the scene becomes active, by a timer while open (Settings → Data, default 15 min), by the refresh button / ⌘R / pull to refresh (forced), and on iOS by a `BGAppRefreshTask` (`com.gauthamv.openfeed.refresh`).
- Full text: `ContentService.content(forItem:refresh:)` returns cached `items.content_html` or calls `DefaultContentExtractor`: fetch the page (403 retried once with browser headers), run Readability.js in a hidden non-persistent `WKWebView` (page JavaScript off), apply the cleanup passes, sanitize with SwiftSoup (img, picture/source, pre, code, a, headings, lists, blockquote, figure, figcaption, video, shape-only inline SVG, iframes from youtube-nocookie/Vimeo), and cache it. Fallbacks: the feed's own content:encoded, then a Jina Reader render. Skipped for YouTube; podcasts use show notes from the feed.

## App behavior (replaces the HTTP API)

- Items: `AppModel` pages through `Queries.items` (views all/saved/articles/posts/video/podcasts, source or folder, search, keyset cursor on published_at desc, 50 per page).
- Sources: add (`OpenDispatchServices.addSource` → `DefaultFeedDetector`: YouTube handles/channels, Apple Podcasts, alternate links, www retry, scraped-page fallback), rename, move, reorder, delete; folders likewise. OPML import/export via the file importer/exporter.
- Save/unsave is optimistic. Send to Readwise Reader (token in the Keychain) or a webhook (URL in `meta`).
- Highlights and notes: `HighlightStore` (App/Model, an `@Observable` in the environment next to AppModel) observes the highlights table and makes the edits. The reader injects `Resources/reader-highlights.js` into the article web view (content world `defaultClient`): it indexes the article's normalized text (whitespace collapsed, a space at block boundaries and `<br>`, every character mapped back to its text node), turns a selection into a text-quote anchor, resolves each stored quote back to a Range (exact text, ties broken by prefix/suffix) and paints one CSS Custom Highlight per color (`::highlight(od-hl-<color>)` in reader.css) without touching the DOM. It reports taps (with the rect of the clicked line), right-clicks and where each highlight is; the reader scrolls its own ScrollView to a marker placed at that offset, and `flash(id)` blinks the highlight there (a ::highlight(od-hl-flash) over its color). A highlight with a note also gets a note marker: a `<button class="od-note-marker">` (ring and square in its color, `--hl-solid-*`) in one absolutely positioned zero-size host appended to `<body>` after the article, level with the highlight's first line in the margin of the text column; it is outside the article and out of flow, so the fitted height, the text index and read aloud never see it, it is placed again by a ResizeObserver on the article (and on resize, load and fonts ready), and clicking it reports a tap like the highlight. Nothing sits beside the article: its width never depends on highlights. Click (tap) a highlight or marker: `HighlightStore.popover` opens `HighlightPopover` (colors and Underline, note, remove, the note text) as a SwiftUI `.popover` on the article web view, anchored (`attachmentAnchor: .rect`) to the reported rect; it closes on Esc, an outside click, or when the web view's frame in the window changes (the reader scrolled or the pane resized); on iPhone `presentationCompactAdaptation(.popover)` keeps it a popover. Add Note…, Edit Note… and the popover's note open `HighlightNoteSheet` (`HighlightStore.noteRequest`, presented by `readerHighlights(item:pane:compact:)` on the pane): the highlight's time, the quote with its color bar, a text editor, Cancel and Done (a bottom sheet on iPhone). The reader bar's highlighter button opens `HighlightsList` (document order, the quote clamped to three lines, the note, Copy as Markdown, the Readwise line) as a popover under it, a sheet on iPhone; picking an entry closes it and scrolls to the highlight. Mac: a right-click menu with the colors, Add Note… and for an existing highlight the colors, Edit Note…, Remove Highlight. iPhone: the edit menu (`ReaderFittedWebView.buildMenu`). The Highlights view is `AppModel.showsHighlights` (a navigation state under Saved) with `HighlightStore.groups` as its rows. With a Readwise token and "Send highlights to Readwise" on, `ReadwiseHighlightSync` (Core) creates a highlight with `POST /api/v2/highlights/` (a unique `highlight_url` per highlight, response `modified_highlights` gives the id, then a `PATCH` for the color), updates its note and color with `PATCH /api/v2/highlights/<id>/`, and deletes with `DELETE`; only changes made on this device are queued.
- Read state and History: `HistoryStore` (App/Model, owned by AppModel as `model.history`) observes the history table. An item is recorded as opened when a pane's active tab newly shows it (`AppModel.recordShownItems`; the list's first item shown by default on the Mac and iPad doesn't count): an article or post becomes read then, a video or episode only once played past 90% (`HistoryEntry.finishedFraction`). The YouTube player reports its position and length each second and the podcast player when it saves its position; `HistoryStore.recordProgress` writes at most every 10 s while playing and at once on pause, seek, leaving and the end, and the next open resumes there (the podcast's own UserDefaults position first). Mark as Read / Unread (Watched / Played for videos and episodes) is in the row menus and `m`; Mark All as Read marks every item of the current list (all pages). Hide Read Items (`AppSettings.hideReadItems`: the list title menu on the Mac and iPad, pressing and holding the title on iPhone, Settings → Appearance) leaves out items read before the list last loaded (`ItemQuery.hideReadBefore`, moved on navigation and refresh), never in Saved or a search, so nothing vanishes while you look. The History view is `AppModel.showsHistory` (sidebar and drawer row after Highlights, `g h`): opened entries grouped by day (Today, Yesterday, the weekday, then the date), drawn as feed rows with the time opened, search over titles and sources, Clear (the header's trash button, or Clear by the iPhone title) with Last Hour / Today / Today and Yesterday / All History, and per row Open in New Tab, Open Original, Mark as Read / Unread, Copy Link and Remove from History (iPhone: swipe left to remove; the feed lists have no swipe actions since a sideways swipe there changes views). Opening an entry whose item was pruned adds it back from the snapshot (`Queries.itemForHistory`), or opens the link in the browser when its source isn't here.
- iCloud sync (`Core/Sources/OpenDispatchCore/Sync`): `CloudSync` runs a `CKSyncEngine` on the private database, zone `OpenDispatch`, container `iCloud.com.gauthamv.openfeed`. Record types: Folder (named by lowercased title), Source (named by feed URL; title, folder title, position, pin, hidden, plus kind/group/url/icon for inserting), SavedItem (named by source feed URL + guid; an item snapshot), History (named by source feed URL + guid; the row with the position in whole seconds, and `progressPct` (5% steps) in place of it in the hash, so playback isn't an upload every few seconds; a save conflict takes the server's copy), Highlight (named by the highlight's id; every column above except `readwise_pending`; a change from iCloud never queues a Readwise send, and a save conflict takes the server's copy), Settings (the AppSettings JSON, mirrored into `meta` `sync.settings`) and Integrations (webhook URL; Readwise token in encrypted values). Feed items are not synced. Highlight and History records (`SyncRecordType.late`) are each sent in batches of their own and, when CloudKit rejects the type (not yet in the Production schema; `App/CloudKit/schema.ckdb` has both), held back for 30 minutes without touching the other records. `SyncStore` diffs the tables against `sync_records` a moment after any write to sources/folders/items/meta, so app code never calls into sync. Hashes cover only user-editable fields so each device's refresh bookkeeping (icons, item titles) is not a change. Incoming changes are applied and shadowed in one transaction; on a save conflict the server's copy wins. A device's first sync fetches everything, then, if the device is still as seeded (nothing saved, pinned, hidden or added beyond the seed) and iCloud has a library, drops the seeded sources and empty folders iCloud doesn't have; otherwise it merges. Then it uploads. Saved items that arrive before their source wait in `sync_parked`. Signing out of iCloud keeps the local library and forgets the sync state. Settings → Data has the per-device toggle (UserDefaults `openfeed.icloud-sync`, default on) and status; it also syncs when the scene becomes active.
- Read aloud (`Views/Reader/ReaderSpeech*.swift`): the reader's Listen button (⇧⌘L, View menu) speaks the headline and the article with `AVSpeechSynthesizer`, one utterance per sentence, the next queued so there is no gap. Sentences come from the article web view (`ReaderSpeechScript`: `Intl.Segmenter` over p, li, headings, blockquote, figcaption and loose container text, skipping `pre`, hidden and aria-hidden text, with English abbreviations rejoined), each with a DOM Range; the one being spoken is highlighted with the CSS Custom Highlight API (`::highlight(od-speech)`, no DOM change) and the reader's enclosing scroll view follows it when it nears an edge, until the reader scrolls by hand (resumes on play, previous or next). A player bar (Mac: bottom of the pane; iPhone: above the bottom safe area) has previous, play / pause, next, speed (the podcast steps) and close, and shows elapsed / estimated total time. A click or tap on a sentence jumps there; Read Aloud from Here (right-click menu on the Mac, edit menu on iPhone) starts at the selection. Playback belongs to the reader like the podcast player's: leaving the article stops it. iOS audio session `.playback` / `.spokenAudio`, Now Playing and remote commands (next / previous track step a sentence); it and the podcast pause each other. `AppSettings.speechVoice` (nil: best installed voice, Premium > Enhanced > default; an id this device lacks falls back to it) and `speechRate` are set in Settings → Playback.
- SponsorBlock (`Core/.../SponsorBlock/`, `Views/Settings/SettingsSponsorBlockSection.swift`): the YouTube player skips, mutes or marks the segments viewers have submitted to SponsorBlock (sponsor.ajay.app, CC BY-NC-SA 4.0). `DefaultSponsorBlock` (`OpenDispatchServices.sponsorBlock`) asks `GET /api/skipSegments/<first 4 hex of SHA-256(video id)>` for every category (`actionTypes` skip, mute, full, poi) and picks its video from the answer; 404 is no segments, results (empty too) are kept in memory for 24 h, and a failure returns nothing quietly and isn't kept. When the reader's player is created (and on any settings change) the app maps the segments through the settings (`SponsorBlock.playerSegments`: Off drops a category; Skip / Mute / Show on bar give the action `skip` / `mute` / `show`; whole-video labels are `full`, highlights `poi`) and pushes them to the player page with `window.odPlayer.setSegments(json)` (or `window.odPendingSegments` before the page has defined it), again after each page load, and to the iPhone full-screen cover's second player. Settings → Playback → SponsorBlock: a master switch (`AppSettings.sponsorBlock`, default on) and one mode per category with its SponsorBlock color (`sponsorBlockModes`, only non-default entries stored). Defaults: sponsor, selfpromo, interaction Skip; intro, outro, preview, hook, poi_highlight, exclusive_access Show on bar; filler, music_offtopic Off. Highlight and exclusive access offer only Show / Off; non-music section no Mute.
- Opened links (`OpenDispatchServices.openLink`): the link is normalized, then stored as an item of an `OpenedLinks` holder source (pages, YouTube videos, podcast episodes; hidden from `Queries.sources` and the feed views, Saved only, pruned by `created_at`, recreated by a saved item or highlight arriving from iCloud). A YouTube link takes the video id; an Apple Podcasts episode link (`podcasts.apple.com` or `itunes.apple.com` with `?i=<episode>`) is stored under one address (`https://podcasts.apple.com/<store>/podcast/id<show>?i=<episode>`) and resolved with the iTunes lookup of its show (`ApplePodcastEpisode`: the newest 20 episodes, then 200, since the API can't look up one episode), falling back to the show's feed matched by the page's title; a link ending in an audio extension, or answering HEAD with `audio/*`, becomes an episode named from the file name. Those get the podcast player, with the show (or the file's host) as their source. A show link without `?i=`, Spotify and every other page open as articles from their metadata (the site-name tail of the title is dropped, and a login-shell title falls back to the address). An opened episode's feed is not stored: show notes (`ContentService`) and the transcript (`DefaultTranscriptFetcher`) look the show's feed up again from the Apple address and find the entry by its audio URL; an audio file has neither.
- Social posts (`Core/.../Extraction/Social/`): a link to a post on X (`TweetExtraction`), Bluesky, Mastodon, LinkedIn, Threads or Instagram reads as a post in the reader (`.x-post` markup: author row with avatar and handle, text with links, photos / video / GIF, quoted post, link card, date and "Open on …" footer) and is titled by its first paragraph with the author as `Name (@handle)` (`SocialPost.item`, used by `DefaultPageScraper.fetchLinkItem` for opened links; feed items from these networks get the same reader view). `SocialPosts.network(of:)` tells them apart by address and `TextFormat.isSocialPost` is what the app asks. Sources, all without an account: Bluesky's public AppView `getPostThread` (facets are UTF-8 byte ranges; images, link card, video as an HLS playlist with its still, quote, quote with media); Mastodon's `/api/v1/statuses/<id>` on the address's own server (`https://<host>/@user/<id>`; content warning, custom emoji, photos / video / GIF, link card, accepted quotes, the "RE:" line dropped); LinkedIn's public post page (`lnkd.in` links followed, the stored address is the linkedin.com post without its utm / rcm query; the commentary, the actor link, the best MP4 and its cover or the photos, the post's date from JSON-LD; `linkedin.com/redir/redirect?url=` wrappers opened; no avatar, which logged-out pages don't carry); Threads and Instagram from the Open Graph tags (and the embed page's avatar and, for Threads, day) their pages give a link-preview crawler (`facebookexternalhit` User-Agent; a browser gets a login wall), picture only (a video is its still). A Threads or Instagram post that can't be read is titled "Post by @user on Instagram" and the reader shows its failure state with Open original. Tests use saved fixtures (`Fixtures/Social`).
- Deep links: `opendispatch://add?url=<url>` opens Add source prefilled; `opendispatch://settings?tab=<pane>` opens Settings on a pane. The old `openfeed://` scheme is still accepted.

## Platform

- macOS: three-pane `NavigationSplitView` with a hidden title bar and translucent sidebar; menu commands (Check for Updates…, Settings ⌘,, Add Source ⌘N, Refresh ⌘R, Reload Article ⇧⌘R, Listen ⇧⌘L, Search ⌘F, Filter Sources ⌘K, New Tab ⌘T, Open Link ⌘L, Close Tab ⌘W, Reopen Closed Tab ⇧⌘T, Sidebar ⌘\, Full-screen reader ⇧⌘F, Split View ⌥⌘S, next/previous tab ⇧⌘] / ⇧⌘[, Pin Tab, Shortcuts ⌘/); Settings is an overlay panel in the main window; reader tabs and split view (each pane's bar always shows its tabs, even one, then + for a new tab; a new tab has an address field (focused on open and by ⌘L) for any link, stored as an item of a built-in, unlisted source (`OpenedLinks`: one for pages, one for YouTube videos, one for podcast episodes; left out of `Queries.sources`, so never refreshed, listed, exported or synced as a source; its items list only in Saved and are pruned 14 days after opening unless saved), then recently read (History) and saved items, and the next item opened fills it; closing the last tab leaves a new tab, and ⌘W on that closes the window; pinned tabs (tab right-click or View › Pin Tab) sit leftmost as source badges, keep their item, so a list click or j/k on one opens a new tab after the pins, skip ⌘W and Close Other Tabs, are never repeated by the default tab (which shows the first unpinned item), and are restored on launch from UserDefaults `openfeed.pinned-tabs`, in one pane); single-key shortcuts in the main window. Updates through Sparkle from the latest GitHub release's appcast; releases are Developer ID signed, notarized DMGs (scripts/release-mac.sh). Sandboxed with outgoing network and user-selected file access, iCloud (CloudKit, Production environment in every build) and push notifications.
- iPhone (iOS 26): system TabView and navigation bars with Liquid Glass, no title text; the reader's Save / Open original / Share / Send to sit in the system bar; navigation stacks, pull to refresh. iPad: the three-pane layout with hardware-keyboard shortcuts.
- App icon in `App/OpenDispatch/Resources/Assets.xcassets` (rendered from `design/app-icon.svg` by `scripts/render-icons.sh`; toolbar and sidebar icons are custom symbols from `scripts/make-icons.swift`). ATS allows plain-http feeds, images and audio; background modes: fetch, audio (podcasts), remote-notification (CloudKit pushes).
- Offline: the local database is the cache; the last-loaded items and cached articles open without a network.

## Non-goals

No accounts or auth of our own (iCloud sync uses the device's Apple ID), no server, no multi-user, no sync of feed items (read state and History sync, as their own records). (The web app's `APP_PASSWORD`, `CRON_SECRET`, Vercel cron, PWA manifest and service worker are gone.)
