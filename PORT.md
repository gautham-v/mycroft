# OpenDispatch native port: shared contract

> Historical: the contract used while porting the web app to Swift (October 2026), when the app was
> still called Openfeed. Names and paths are updated to OpenDispatch; identifiers that carry user
> data (`com.gauthamv.openfeed`, `openfeed.*` UserDefaults keys, `openfeed.sqlite`, `openfeed:kind`)
> keep the old name. README.md and SPEC.md describe the app as it is now.

OpenDispatch is being ported from the Next.js web app (`src/`, the reference implementation) to a native
SwiftUI app for macOS 15 and iOS 26. Everything runs locally: there is no server, no auth and no sync.
This file is the contract between the agents doing the port. **Read all of it before writing code.**
If you add public API, add it in files you own and document it under **Additions** at the bottom
(append only, never edit earlier sections).

Status when Foundation finished: `swift build` and `swift test` (32 tests) pass in `Core/`; the app
builds for macOS and the iPhone 16 Pro simulator (iOS 18.4) and launches on macOS, creating and
seeding its database. All Default* services are placeholders except where noted.

## 3. Conventions (all agents)

1. **One module, one namespace.** Everything in Core is in module `OpenDispatchCore`. Never declare
   module-level `internal` free functions, globals or helper types with generic names (`Regex`,
   `Helpers`, `stripHtml`, `parse`...): another agent will collide with you. Put helpers inside your
   type, a caseless `enum` named after your area (`enum FeedParsingSupport`), or mark them `private` /
   `fileprivate`. The app target is a separate module; the same rule applies inside it.
2. **Replace placeholders, keep the name.** Each `Default*` file is a placeholder that its owner replaces
   wholesale. Keep the type name, its protocol conformance and the exact `public init` shown in section 5,
   because `OpenDispatchServices.live` constructs them. You may make a struct a `final class` (must stay
   `Sendable`; `@unchecked Sendable` with internal locking or `@MainActor` isolation of internals is fine).
3. **Protocols are frozen.** Don't change a protocol signature. If you need more, add a new method in an
   extension with a default implementation, or a new type, and document it in Additions.
4. **No force unwraps** (`!`, `try!`, `as!`) on anything derived from the network, files or the database
   contents. Throw instead. (`try!` on in-memory database creation in previews is the only exception.)
5. **Errors shown to the user** must have a readable `localizedDescription`: conform to `LocalizedError`.
   `HTTP.message(error)` converts any error to the user-facing string (port of `errMsg`).
6. **Networking** goes through `HTTP.fetch` / `HTTP.fetchOK` (Support/HTTP.swift): it sets the OpenDispatch
   User-Agent, a timeout, no cache, and maps timeouts to `HTTPError.timedOut` ("Timed out"). Decode
   bodies with `HTTP.text(data, response:)` (charset-aware). Use `HTTP.browserHeaders` for the 403 retry.
7. **Dates**: `Date` everywhere. GRDB stores them as `"yyyy-MM-dd HH:mm:ss.SSS"` UTC text, which sorts
   correctly. Use `ISO8601.string(from:)` / `ISO8601.date(from:)` for wire/meta strings (JS `toISOString`).
8. **IDs** are `Int64`. Records use `id == 0` for "not inserted yet"; `insert` fills it in.
9. **Database access**: use the async wrappers on `AppDatabase` for single operations, or
   `try await appDatabase.writer.write { db in ... Queries.x(db, ...) }` to group several in one
   transaction. Never hold a transaction across `await`. Foundation owns the schema
   (`AppDatabase.migrator` in Database/AppDatabase.swift): don't add tables or columns yourself; if you
   need one, report it to the orchestrator instead (store small key/values in `meta`).
10. **Concurrency**: services are `Sendable` and called from the `@MainActor` AppModel with `await`.
    Do slow work off the main actor. WebKit work (Readability, reader view) must run on the main actor.
11. **Design**: no emoji, no gradients, SF Symbols outline variants (OFIcon) for icons, tokens from
    Design/Tokens.swift (`Color.ofInk`, `.foregroundStyle(.ofMuted)`), fonts from `OFFont`, sizes from
    `Metrics`. Never hard-code a hex color in a view. Support light and dark (tokens are dynamic) and
    the forced theme in `AppSettings.theme` (RootView applies `.preferredColorScheme`).
12. **No git state changes**, don't edit files outside your directory, don't delete web-app files.
13. Tests: swift-testing (`@Test`, `#expect`, `#require`). Never hit the network in tests; use fixture
    strings/files under `Core/Tests/OpenDispatchCoreTests/Fixtures/<YourArea>/` (create the folder; if you
    add resource files, tell the orchestrator so `Package.swift` gets a `resources:` entry for the test
    target, or embed fixtures as Swift string literals, which is simpler).

## 4. Data model (Core/Sources/OpenDispatchCore/Models)

SQLite schema (migration "v1" in Database/AppDatabase.swift), mirroring `src/db/schema.ts`:

```
folders  id INTEGER PK AUTOINCREMENT, title TEXT NOT NULL, position INTEGER NOT NULL DEFAULT 0, created_at DATETIME
sources  id PK, title, url, feed_url UNIQUE, kind TEXT CHECK in (rss,youtube,page,podcast), "group" TEXT,
         icon_url, last_fetched_at, last_error, seen_urls TEXT (JSON array), folder_id → folders ON DELETE SET NULL,
         position INTEGER, created_at
items    id PK, source_id → sources ON DELETE CASCADE, guid, url, title, summary, content_html,
         content_rendered BOOL, author, published_at DATETIME NOT NULL, thumbnail_url, thumbnail_checked BOOL,
         video_id, duration_sec, audio_url, hn_points, hn_comments, hn_comments_url, is_saved BOOL, created_at
         UNIQUE(source_id, guid); INDEX(published_at DESC, id DESC); partial INDEX(is_saved) WHERE is_saved = 1
meta     key TEXT PK, value TEXT NOT NULL
```

SQL function registered on every connection: `opendispatch_is_post(url)` (PostSource.isPostURL). No FTS:
search is LIKE over title/summary/author/content_html (ASCII case-insensitive), same as the web app's ILIKE.

### RefreshService (Fetching/) — port of src/lib/fetcher.ts and dedupe.ts
```swift
public protocol RefreshService: Sendable {

    @discardableResult func refreshSource(id: Int64) async throws -> Int     // items added

public struct RefreshResult: Sendable, Hashable { ran: Bool; lastRefreshAt: Date?; results: [SourceRefreshResult]; pruned: Int }
```

The placeholder already does the stale check (`RelativeTime.isStale`, 15 min), claims `last_refresh_at`

  `AppModel.handleOpenURL(_:)` sets `pendingAddSourceURL` and presents Add source; `AddSourceView` prefills from it.
  `opendispatch://settings?tab=<sources|appearance|playback|integrations|data|about>` calls `showSettings(_:)`.
  Debug builds also take a launch argument `-OFSettingsTab <tab>` (RootView) to open a pane at launch, for
  driving Settings from the command line (`xcrun simctl launch booted com.gauthamv.openfeed -OFSettingsTab data`).
- RootView attaches `.openDispatchAutoRefresh()`; macOS split view uses `.toolbar(removing: .title)`.
- project.yml: `NSAppTransportSecurity.NSAllowsArbitraryLoads` (plain-http feeds, images, audio) and
  `UIBackgroundModes: [fetch, audio]`.
- **iOS 18 launch fix:** never call WebKit's Swift-overlay JS methods (`evaluateJavaScript(_:in:in:completionHandler:)`,
  `callAsyncJavaScript(...)` with Result or async). Built with the iOS 26 SDK they link `libswiftWebKit.dylib`, which
  iOS 18 lacks, and the app dies at launch with "Library missing". Use the ObjC entry points
  `__evaluateJavaScript(_:inFrame:in:completionHandler:)` / `__callAsyncJavaScript(_:arguments:inFrame:in:completionHandler:)`.
  Check with `dyld_info -imports <app>/OpenDispatch.debug.dylib | grep libswiftWebKit` (should print nothing).
- ItemListView keeps the list at the top when a refresh inserts newer items above a top-scrolled list.
- ReaderText.contentHasHero also matches the content's leading image by normalized file name (WordPress size/crop
  variants), so the hero isn't shown twice.
